# Serve Misc (PR Group 10) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix serve-mode hygiene bugs — slug collisions (BUG-43), executor blocking (BUG-44), idle-session leaks (BUG-08), stale landing counts (BUG-45) — and add session resume (FEAT-03).

**Architecture:** All work is confined to serve mode (`src/cmd/serve/`), plus one new query in `src/db.rs`. Blocking work moves onto `tokio::task::spawn_blocking` following the existing pattern at `src/cmd/serve/git.rs:153`. Idle sessions gain a `last_activity_at` timestamp on `DrillSession` and are evicted by a background task that also closes their DB session rows. FEAT-03 builds on that: the landing page offers "Resume session (N cards remaining)" for live in-memory sessions, the start endpoint stops silently discarding them, and dangling DB session rows (left by a crash/restart) are closed and reported — they cannot be rehydrated because the card queue lives only in memory.

**Tech Stack:** Rust, axum 0.8, maud, rusqlite, tokio, chrono (naive timestamps), toml.

**Spec:** SPEC.md

## Global Constraints

Copied verbatim from SPEC.md "Global requirements":

- Every bugfix starts with a failing regression test.
- No `unwrap()` in production code; use `Fallible`, `?`, and `fail()`.
- All error messages are user-facing and clear.
- Reviews and performance are written in one transaction; undo voids, never deletes.
- Cloze positions are byte positions: `.bytes()`, never `.chars()`.
- Update `CHANGELOG.xml` per item.

Plan-local notes (not from the spec):

- The existing serve code uses `.lock().unwrap()` on `std::sync::Mutex` throughout. The sweep to remove those is BUG-50 (PR group 6), NOT this PR. New code in this plan follows the existing `.lock().unwrap()` pattern for consistency; do not introduce a third pattern here. All other new fallible paths use `Fallible`/`?`/`fail()`.
- Dates/timestamps are naive on purpose (see CLAUDE.md). Idle/staleness comparisons use `Timestamp` (naive local) and `chrono::Duration`; a clock rollback at worst delays an eviction or a refresh, which is acceptable.
- `Fallible<T>` is `Result<T, ErrorReport>` (`src/error.rs:128`); `fail(msg)` returns `Err(ErrorReport)` (`src/error.rs:130`); `ErrorReport::new(msg)` constructs the error directly.
- Prefer `use` imports over fully qualified paths (project rule).
- Ordering constraint: Task 4 (BUG-08) must land before Task 6 (FEAT-03).
- Run tests with `cargo test` from the repo root. Integration tests for serve mode live in the `#[cfg(test)] mod tests` block of `src/cmd/serve/mod.rs` and follow the existing `test_start_with_multiple_decks` pattern (portpicker + tempdir + reqwest against an in-process server).

/// Reject collections whose names map to the same URL slug.
///
/// `slugify` collapses every non-alphanumeric character to `-`, so distinct
/// paths like `a/b` and `a-b` collide and would silently share one database.
fn check_slug_collisions(collections: &[ResolvedCollection]) -> Fallible<()> {
    let mut seen: HashMap<&str, &ResolvedCollection> = HashMap::new();
    for rc in collections {
        if let Some(first) = seen.get(rc.slug.as_str()) {
            return fail(format!(
                "configuration error: collections '{}' and '{}' both map to the URL slug '{}'. Rename one of them so their slugs differ.",
                first.name, rc.name, rc.slug
            ));
        }
        seen.insert(rc.slug.as_str(), rc);
    }
    Ok(())
}
```

/// BUG-44 regression: a slow collection load must not stall the whole
/// server. Runs on a single-threaded runtime and replaces the deck file
/// with a FIFO (named pipe): reading it blocks until a writer connects,
/// simulating a slow disk. Before the fix, the blocked handler froze the
/// only executor thread, so the landing page could not respond until the
/// FIFO was unblocked (>= 5s); after it, the landing page answers
/// immediately.
#[cfg(unix)]
#[tokio::test(flavor = "current_thread")]
async fn test_blocking_collection_load_does_not_stall_server() -> Fallible<()> {
    use std::time::Duration;
    use std::time::Instant;

    let port = pick_unused_port().unwrap();
    let dir = tempdir()?;
    let coll_dir = dir.path().to_path_buf();
    let deck_path = coll_dir.join("Deck.md");
    write(&deck_path, "Q: What is 1+1?\nA: 2\n")?;

    let slug = "fifo-collection".to_string();
    let config = ResolvedServeConfig {
        host: TEST_HOST.to_string(),
        port,
        git: None,
        defaults: DefaultsSection::default(),
        collections: vec![ResolvedCollection {
            name: "Fifo Collection".to_string(),
            slug: slug.clone(),
            coll_dir: coll_dir.clone(),
            db_path: coll_dir.join("hashcards.db"),
        }],
        data_dir: None,
        config_path: None,
        hedgedoc_entries: Vec::new(),
        _temp_dir: None,
    };
    spawn(async move { start_serve(config).await });
    wait_for_server(TEST_HOST, port).await?;

    // Replace the deck file with a FIFO; reads now block until a writer opens it.
    std::fs::remove_file(&deck_path)?;
    let status = std::process::Command::new("mkfifo").arg(&deck_path).status()?;
    assert!(status.success(), "mkfifo failed");

    // Unblock the FIFO after 5 seconds no matter what, from a plain OS
    // thread that is immune to a stalled runtime.
    let writer_path = deck_path.clone();
    let writer = std::thread::spawn(move || {
        std::thread::sleep(Duration::from_secs(5));
        let _ = std::fs::write(&writer_path, "Q: What is 1+1?\nA: 2\n");
    });

    let base = format!("http://{TEST_HOST}:{port}");
    let client = reqwest::Client::new();
    let started = Instant::now();
    // This request blocks server-side reading the FIFO (deck browser reload).
    let slow = tokio::spawn(client.get(format!("{base}/collection/{slug}")).send());
    // Give the slow request time to reach the blocking read.
    tokio::time::sleep(Duration::from_millis(200)).await;
    // The landing page must still respond while the collection load is stuck.
    let landing = client.get(format!("{base}/")).send().await?;
    assert!(landing.status().is_success());
    assert!(
        started.elapsed() < Duration::from_secs(3),
        "landing page stalled for {:?} behind a blocking collection load",
        started.elapsed()
    );
    let _ = slow.await;
    let _ = writer.join();
    Ok(())
}

/// Run blocking filesystem/SQLite work on tokio's blocking thread pool.
///
/// Serve handlers parse collections from disk and touch SQLite; doing that
/// on the async executor stalls every other request (BUG-44). Pattern as in
/// `git.rs` (`spawn_blocking` in `spawn_sync_task`).
pub(super) async fn run_blocking<T, F>(f: F) -> Fallible<T>
where
    F: FnOnce() -> Fallible<T> + Send + 'static,
    T: Send + 'static,
{
    tokio::task::spawn_blocking(f)
        .await
        .map_err(|e| ErrorReport::new(format!("Internal error: a background task failed: {e}")))?
}
```

### Task 4: BUG-08 — Evict idle sessions and document single-user semantics

```rust
/// Remove sessions idle for at least `timeout_minutes` and close their DB
/// session rows. `timeout_minutes == 0` disables eviction. Returns the
/// evicted slugs.
///
/// DB work happens after the map lock is released, so eviction never holds
/// the sessions lock across SQLite calls.
pub fn evict_idle_sessions(
    sessions: &std::sync::Mutex<HashMap<String, DrillSession>>,
    timeout_minutes: u64,
    now: Timestamp,
) -> Vec<String> {
    if timeout_minutes == 0 {
        return Vec::new();
    }
    let timeout = Duration::minutes(timeout_minutes as i64);
    let expired: Vec<(String, DrillSession)> = {
        let mut map = sessions.lock().unwrap();
        let keys: Vec<String> = map
            .iter()
            .filter(|(_, s)| now.into_inner() - s.last_activity_at.into_inner() >= timeout)
            .map(|(k, _)| k.clone())
            .collect();
        keys.into_iter()
            .filter_map(|k| map.remove(&k).map(|s| (k, s)))
            .collect()
    };
    let mut evicted = Vec::new();
    for (slug, session) in expired {
        if session.mutable.finished_at.is_none() {
            if let Err(e) = session
                .mutable
                .db
                .close_session(session.mutable.session_id, now)
            {
                log::error!(
                    "Failed to close evicted session {} for collection '{slug}': {e}",
                    session.mutable.session_id
                );
            }
        }
        evicted.push(slug);
    }
    evicted
}
```

fn spawn_session_eviction_task(
    sessions: Arc<Mutex<HashMap<String, DrillSession>>>,
    timeout_minutes: u64,
) {
    if timeout_minutes == 0 {
        log::debug!("Idle session eviction disabled (session_timeout_minutes = 0)");

        // Check at a quarter of the timeout, capped at every 10 minutes.
        let tick_secs = (timeout_minutes * 60 / 4).clamp(1, 600);
        let mut ticker = tokio::time::interval(std::time::Duration::from_secs(tick_secs));
        ticker.tick().await;

            ticker.tick().await;
            let sessions = sessions.clone();

                evict_idle_sessions(&sessions, timeout_minutes, Timestamp::now())

                        evicted.join(", ")
                    );
                }
                Ok(_) => {}
                Err(e) => log::error!("Session eviction task failed: {e}"),

        }
    });

### Task 6: FEAT-03 — Session resume

Reviews persist immediately, so an unfinished session is worth surfacing instead of silently replacing. Two cases:

1. **Live in-memory session** (in the `sessions` map): the landing page shows "Resume session (N cards remaining)" linking to `/collection/{slug}` (which renders the running session), and `POST /collection/{slug}/start` refuses to discard an unfinished session — it becomes a redirect back to the running session.
2. **Dangling DB session row** (server crashed/restarted; the map is empty but the DB has an unclosed row). Rehydration decision: **infeasible** — the card queue, deck filter, card limit, shuffle order, and undo stack live only in `MutableState` in memory (`src/cmd/drill/state.rs:41-51`); the DB stores only reviews. So a dangling row is **closed and reported**: `close_dangling_sessions` closes it at the time of its last surviving review (or its start time if no review survives), and the deck-browser page shows a one-time notice. A dangling row is detectable because `create_session` writes `ended_at = started_at` as a placeholder (`src/db.rs:244-253`; the column is `NOT NULL`), so `ended_at = started_at` identifies never-closed rows. Alignment with BUG-08: eviction (Task 4) closes rows for abandoned live sessions, so dangling rows only stem from crashes/restarts — the two mechanisms never race over the same session.

Known benign edge cases of the `ended_at = started_at` marker (document in the code as written below): a genuinely instantaneous session is rewritten to the same value; a row mid-creation by a racing start POST may be "closed" early, but `finish_session`/`close_session` simply overwrite `ended_at` later.

    /// Close sessions left dangling by a crash or restart.
    ///
    /// `create_session` writes `ended_at = started_at` as a placeholder, so
    /// a row where the two are still equal was never closed. Each such row
    /// is closed at the time of its last surviving (non-voided) review, or
    /// left at `started_at` if no review was recorded. Returns the number
    /// of rows touched.
    ///
    /// A genuinely instantaneous session matches the predicate too; it is
    /// rewritten to the same value, which is harmless. Likewise, a row
    /// belonging to a session mid-creation may be touched; `close_session`
    /// simply overwrites `ended_at` later.
    pub fn close_dangling_sessions(&self) -> Fallible<usize> {
        let sql = "update sessions set ended_at = coalesce((select max(reviewed_at) from reviews where reviews.session_id = sessions.session_id and reviews.voided = 0), started_at) where ended_at = started_at;";
        let rows = self.conn.execute(sql, [])?;
        Ok(rows)
    }

4. **FEAT-03's "silently starting over" is narrower than it sounds for live sessions.** A GET of `/collection/{slug}` with a live session already renders that session (de-facto resume); the real silent-discard paths are the start POST (`handlers.rs:234` removes any existing session) and the invisible landing page (no resume indication). The plan addresses all three; true rehydration of a dangling row is infeasible because the queue/filter/limit/shuffle/undo state exists only in `MutableState` (`src/cmd/drill/state.rs:41-51`) — confirmed, per the spec's own suspicion.
5. **Spec's BUG-08 default "e.g. 24h"** is implemented as `session_timeout_minutes = 1440` (minutes rather than hours) so tests and short-lived deployments can configure sub-hour timeouts; `0` disables eviction, mirroring the existing `poll_interval_minutes = 0` convention (`git.rs:118-121`).
